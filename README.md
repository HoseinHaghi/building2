# ساختمان — مدیریت پروژه و کار

برنامه‌ی فارسی و راست‌به‌چپ برای پروژه‌های مشترک، زیرپروژه‌ها، کارهای هفت طبقه، مسئولان و گزارش‌ها. فرانت‌اند React و بک‌اند Express در محیط نهایی از یک دامنه ارائه می‌شوند.

## وضعیت رابط کاربری

شش صفحه‌ی اصلی از آرشیو دست‌نخورده‌ی BuildingFront-Back.zip بازیابی شده‌اند: ورود/ثبت‌نام، داشبورد و کارهای شما، ساخت پروژه، انتخاب پروژه، ساخت/ویرایش کار و جزئیات کار. چیدمان، رنگ‌ها، فونت، فیلدها، تب‌ها و کنترل‌های اصلی حفظ شده‌اند؛ ارتباط داده و عملیات به API واقعی متصل است. نوار بالای اضافه‌شده و صفحه‌ی تنظیمات جدید حذف شده‌اند. فرم ثبت‌نام اصلی ایمیل ندارد و API ثبت‌نام بدون ایمیل را پشتیبانی می‌کند.

بخش Final فایل Figma هنوز از طریق حساب متصل قابل خواندن نیست؛ این نسخه بازگردانی ظاهر آرشیو اصلی است و تطبیق دقیق با Final تأیید نشده است. پس از فراهم‌شدن دسترسی فایل، باید صفحات و حالت‌های آن بررسی شوند.

ساخت پروژه از دکمه‌ی «+» در نوار کناری داشبورد در دسترس است؛ با بازکردن نوار، عنوان «ایجاد پروژه» روی همین دکمه نمایش داده می‌شود. مسیرهای مستقیم ساخت پروژه و کار: http://localhost:5173/create-project و http://localhost:5173/create-work.

برای ثبت کار در هر پروژه یا زیرپروژه، ابتدا آن را در درخت پروژه‌ها انتخاب کنید و «ایجاد کار» را بالای دکمه‌ی ایجاد پروژه بزنید. فرم با مسیر کامل همان پروژه باز می‌شود و انتخاب پروژه با تازه‌کردن صفحه حفظ می‌شود. اگر پروژه‌ای انتخاب نکرده باشید، می‌توانید آن را داخل فرم انتخاب کنید. شروع کار جدید از داشبورد، فرم تازه‌ای باز می‌کند؛ «انصراف» نیز به داشبورد پروژه‌ی انتخاب‌شده برمی‌گردد.

متن فرم‌های ساخت پروژه و ساخت/ویرایش کار در همان تب مرورگر ذخیره می‌شود و با تازه‌کردن صفحه باقی می‌ماند. عکس و پیوست انتخابی هنگام رفتن به صفحه‌ی انتخاب پروژه و برگشت حفظ می‌شوند؛ پس از بارگذاری کامل دوباره‌ی صفحه، فایل‌های ارسال‌نشده باید دوباره انتخاب شوند. شرح پیش‌نیاز اختیاری است. انصراف، ثبت موفق و خروج از حساب پیش‌نویس مربوطه را پاک می‌کنند.

برای تغییر نام یا حذف پروژه‌ی خالی، پروژه را در نوار کناری انتخاب کنید و منوی سه‌نقطه‌ی کنار نامش را باز کنید. حذف کار در داشبورد و صفحه‌ی جزئیات تأیید می‌خواهد. زیر هر گزارش، آیکون‌های ویرایش و حذف برای نویسنده و مالک پروژه در دسترس‌اند؛ کار تمام‌شده نیز از همان دکمه‌ی پایین صفحه به حالت در حال انجام برمی‌گردد. خروج از حساب از نوار کناری، در هر دو حالت باز و بسته، در دسترس است.

در صفحه‌ی جزئیات هر کار، ضربدر بالای سمت راست کارت، شما را بدون تغییر وضعیت کار به داشبورد همان پروژه برمی‌گرداند.

در فرم‌های «ایجاد پروژه جدید» و «ایجاد کار جدید»، «انصراف» تمام اطلاعات واردشده، انتخاب‌ها و فایل‌های فرم و پیش‌نویس ذخیره‌شده را پاک می‌کند و به داشبورد برمی‌گردد. اطلاعات لغوشده با بازکردن دوباره‌ی فرم، برگشت مرورگر یا تازه‌کردن صفحه بازیابی نمی‌شوند. شروع کار جدید از داشبورد همچنان پروژه‌ی انتخاب‌شده‌ی فعلی را از نو در فرم قرار می‌دهد.

## قابلیت‌های بک‌اند

- ثبت‌نام، ورود و API خروج، تغییر نام و رمز عبور؛ رمزهای scrypt و نشست‌های قابل ابطال در دیتابیس.
- پروژه‌ی خصوصی با مالک و اعضای مشخص؛ عضویت پروژه‌ی اصلی به تمام زیرپروژه‌ها ارث می‌رسد.
- ساخت پروژه و زیرپروژه؛ API تغییر نام، حذف پروژه‌ی خالی و مدیریت اعضا با نام کاربری یا ایمیل دقیق.
- ایجاد، ویرایش و حذف کار، تعیین مسئولان و پایان کار؛ API بازگشایی.
- گزارش‌های دائمی با نام نویسنده و زمان؛ API ویرایش و حذف توسط نویسنده یا مالک پروژه.
- کاور PNG/JPEG/WebP و پیوست خصوصی با دانلود؛ حداکثر هر فایل ۱۰ مگابایت و مجموع فایل‌های هر پروژه‌ی اصلی ۵۰۰ مگابایت.
- درخت پروژه‌ها و نمای طبقات با کارهای واقعی؛ API جست‌وجو، فیلتر و صفحه‌بندی.
- دیتابیس SQLite با کلید خارجی، WAL، تراکنش، مهاجرت نسخه‌بندی‌شده و شناسه‌های غیرقابل استفاده‌ی مجدد پس از حذف.
- محافظت مسیرهای سرور، کوکی HttpOnly/SameSite، CSRF، بررسی Origin، محدودیت درخواست و هدرهای Helmet.

## اجرای محلی

Node **24.13 یا جدیدتر در شاخه‌ی 24** لازم است. ایمیج استقرار روی 24.21.0 تنظیم شده است.

از ریشه‌ی همین پروژه:

```sh
npm ci
npm --prefix server ci
npm run dev:server
```

در ترمینال دوم:

```sh
npm run dev
```

برنامه: http://localhost:5173. برای هماهنگی Origin همین آدرس را باز کنید؛ 127.0.0.1 یک Origin متفاوت است.

Vite درخواست‌های /api را به پورت 5000 پروکسی می‌کند. نیازی به فعال‌کردن CORS یا ذخیره‌ی توکن در localStorage نیست. نشست هفت روز اعتبار دارد و با خروج، انقضا یا تغییر رمز ابطال می‌شود. پس از تغییر رمز، نشست جدید برای همین مرورگر ایجاد و نشست‌های قبلی بسته می‌شوند.

تنظیمات اختیاری سرور را از server/.env.example به server/.env کپی کنید. فضای محلی پیش‌فرض server/storage است و داده‌های نسخه‌ی قبلی به‌صورت خودکار وارد نمی‌شوند.

## مدل دسترسی

| عملیات | افراد مجاز |
|---|---|
| دیدن پروژه، کار، گزارش و فایل | مالک یا عضو پروژه‌ی اصلی |
| ساخت کار و زیرپروژه، ثبت گزارش | مالک یا عضو پروژه |
| تغییر نام/حذف پروژه، افزودن/حذف عضو | مالک پروژه |
| ویرایش/حذف کار و تعیین مسئولان | ایجادکننده‌ی کار یا مالک پروژه |
| تغییر وضعیت کار | ایجادکننده، مالک یا مسئول کار |
| ویرایش/حذف گزارش | نویسنده‌ی گزارش یا مالک پروژه |

«کارهای شما» فقط کارهای ایجادشده یا محول‌شده به همان حساب را نشان می‌دهد. نمای طبقات پروژه کارهای قابل دسترسی آن پروژه را نشان می‌دهد.

حذف عضو دسترسی او به همه‌ی زیرپروژه‌ها و فایل‌ها را قطع و مسئولیت‌هایش را حذف می‌کند؛ گزارش‌ها و سابقه‌ی ایجاد کار برای تیم باقی می‌مانند.

پروژه‌ی دارای کار یا زیرپروژه عمداً حذف نمی‌شود. انتقال کار به پروژه‌ی دیگر هم مجاز نیست تا گزارش و فایل خصوصی به تیم دیگری منتقل نشود. شناسه‌ی کار پس از ویرایش ثابت می‌ماند و نباید شماره‌ی طبقه‌ی فعلی را از آن استخراج کرد.

## استقرار روی Linux با Docker

پیش‌نیاز: Docker Engine، افزونه‌ی Compose، دامنه‌ی متصل به IP سرور و پورت‌های 80 و 443 در دسترس. پورت 5000 برنامه روی اینترنت منتشر نمی‌شود.

1. پوشه‌ی پروژه را بدون node_modules، فایل‌های .env، داده‌های قدیمی و test-results روی سرور قرار دهید.
2. تنظیمات محیط را بسازید:

```sh
cp .env.production.example .env.production
```

مقادیر را در .env.production تنظیم کنید:

```dotenv
DOMAIN=building.your-domain.com
APP_ORIGIN=https://building.your-domain.com
ALLOW_REGISTRATION=true
```

APP_ORIGIN باید دقیقاً شامل پروتکل و دامنه باشد؛ مسیر و اسلش انتهایی نداشته باشد. برای بستن ثبت‌نام عمومی ALLOW_REGISTRATION را false کنید؛ حساب‌های موجود همچنان وارد می‌شوند.

3. اجرا:

```sh
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=100 app caddy
```

4. https://building.your-domain.com را باز کنید، حساب بسازید و پروژه‌ی اول را ایجاد کنید. حساب پیش‌فرض یا رمز دمو وجود ندارد.

Caddy گواهی HTTPS را دریافت و تمدید می‌کند. HTTPS برای کوکی نشست نسخه‌ی نهایی ضروری است. دیتابیس و فایل‌ها در volume ماندگار building_data و گواهی‌ها در caddy_data ذخیره می‌شوند. بازسازی کانتینر داده‌ها را حذف نمی‌کند. از دستور down -v برای نگهداری معمول استفاده نکنید؛ volumeهای داده را حذف می‌کند.

این بسته برای **یک نمونه‌ی برنامه روی یک سرور** طراحی شده است. SQLite و فایل‌های محلی را بین چند replica یا روی فایل‌سیستم شبکه به اشتراک نگذارید. برای مقیاس چند سروری به PostgreSQL و فضای ذخیره‌سازی مشترک نیاز است. node:sqlite در شاخه‌ی Node 24 API آزمایشی محسوب می‌شود؛ نسخه‌ی runtime را پیش از ارتقا با آزمون‌ها بررسی کنید.

## انتقال داده‌های قدیمی

server/data.json و server/uploads نسخه‌ی قبلی دست‌نخورده باقی می‌مانند؛ داخل ایمیج Docker و Git قرار نمی‌گیرند. کاربر demo و رمزهای قدیمی وارد نمی‌شوند.

ابتدا حساب مالک جدید را بسازید. دیتابیس مقصد باید هیچ پروژه‌ای نداشته باشد. سپس در محیط محلی:

```sh
npm --prefix server run import:legacy -- --owner your_username
```

برای منبع دیگر:

```sh
npm --prefix server run import:legacy -- --owner your_username --source /absolute/path/server/data.json
```

uploads باید کنار data.json باشد. ساختار درختی، شناسه‌ها، توضیحات و وضعیت کارها حفظ می‌شوند. فایل‌های موجود کپی می‌شوند؛ فایل ناموجود با هشدار مشخص گزارش می‌شود. در داده‌های فعلی برخی مسیرهای فایل قدیمی موجود نیستند و ابزار انتقال نمی‌تواند آن فایل‌ها را بازیابی کند.

برای انتقال مستقیم روی سرور، یک پوشه‌ی موقت حاوی data.json و uploads را به کانتینر متصل کنید:

```sh
docker compose --env-file .env.production stop app
docker compose --env-file .env.production run --rm --no-deps -v /absolute/legacy-server:/legacy:ro app node server/scripts/import-legacy.js --owner your_username --source /legacy/data.json
docker compose --env-file .env.production start app
```

این انتقال همه‌ی پروژه‌های قدیمی را خصوصی و متعلق به حساب انتخاب‌شده می‌کند. اعضای تیم را پس از انتقال اضافه کنید.

## داده‌های نمونهٔ نسخهٔ اصلی

برای دیدن داده‌های نمونه‌ی رابط اصلی در محیط محلی، ابزار مستقل زیر وجود دارد. این ابزار در حالت production اجرا نمی‌شود و هنگام شروع برنامه به‌صورت خودکار فراخوانی نمی‌شود:

```sh
npm --prefix server run seed:preview -- --owner your_username
```

دستور بالا فقط برنامه‌ی انتقال را نمایش می‌دهد. پس از گرفتن پشتیبان و توقف بک‌اند، با افزودن `--apply` داده‌ها را ثبت کنید:

```sh
npm --prefix server run seed:preview -- --owner your_username --apply
```

نمونه‌ها از کد و داده‌های نسخه‌ی قبلی استخراج شده‌اند: ۶۸ پروژه و زیرپروژه، ۹۹ کار، ۱۹۸ گزارش و مسئولین نمونه. مالک و ایجادکننده‌ی کارها همان حساب انتخاب‌شده است؛ پروژه‌های فعلی تغییر نمی‌کنند. اجرای دوباره برای همان حساب نمونه‌ها را تکرار یا ویرایش نمی‌کند. نام‌های مسئولین و نویسندگان، اشخاص نمونه با نام کاربری `preview_…` و رمز تصادفی اعلام‌نشده هستند و به حساب افراد واقعی متصل نمی‌شوند. فایل‌های قدیمی موجود کپی می‌شوند؛ دو فایل ناموجود قدیمی با هشدار گزارش می‌شوند. سپس بک‌اند را دوباره اجرا کنید و در داشبورد، پروژه‌ی «نرم‌افزار ساختمان / فرانت‌اند / صفحه اصلی ساختمان» یا تب «کارهای شما» را باز کنید.

## پشتیبان‌گیری و بازیابی

برای سازگاری دیتابیس و فایل‌ها، برنامه را هنگام snapshot متوقف کنید. جای تاریخ زیر یک نام جدید قرار دهید:

```sh
docker compose --env-file .env.production stop app
docker compose --env-file .env.production run --rm --no-deps app node server/scripts/backup.js --output /data/backups/2026-10-13
docker compose --env-file .env.production start app
docker compose --env-file .env.production cp app:/data/backups/2026-10-13 ./backups/2026-10-13
```

پوشه‌ی backups مقصد را قبلاً بسازید. یک کپی رمزگذاری‌شده روی دستگاه/فضای دیگری نگه دارید؛ نسخه‌ای که فقط در همان volume است در برابر خرابی دیسک محافظت نمی‌کند. backup شامل building.sqlite، uploads و manifest.json است.

برای بازیابی، برنامه را متوقف کنید و از فایل‌های فعلی یک backup بگیرید. سپس backup را read-only به کانتینر maintenance متصل و دستور restore را اجرا کنید:

```sh
docker compose --env-file .env.production stop app
docker compose --env-file .env.production run --rm --no-deps -v /absolute/backup:/restore:ro app node server/scripts/restore.js --source /restore --replace
docker compose --env-file .env.production start app
```

restore سلامت SQLite و وجود فایل‌ها را بررسی می‌کند، داده‌ی فعلی را در پوشه‌ی retired داخل volume نگه می‌دارد و نشست‌های بازیابی‌شده را باطل می‌کند. کاربران پس از بازیابی دوباره وارد می‌شوند. پس از اطمینان از بازیابی، آرشیو retired را به فضای backup منتقل کنید.

## ساخت یا بازیابی حساب توسط مدیر سرور

API تغییر رمز با دریافت رمز فعلی فراهم است. برای حفظ رابط اصلی، صفحه‌ی تنظیمات تازه‌ای اضافه نشده است. بازیابی خودکار رمز از طریق ایمیل در این نسخه وجود ندارد؛ مدیر سرور از ابزار maintenance استفاده می‌کند.

رمز را در history فرمان ننویسید؛ در Bash:

```sh
read -rs -p "New password: " BUILDING_USER_PASSWORD
export BUILDING_USER_PASSWORD
docker compose --env-file .env.production exec -e BUILDING_USER_PASSWORD app node server/scripts/user.js reset username
unset BUILDING_USER_PASSWORD
```

برای ایجاد حساب هنگام غیرفعال‌بودن ثبت‌نام، همین رمز محیطی را تنظیم و متغیرهای BUILDING_USER_NAME و BUILDING_USER_EMAIL را هم با -e منتقل کنید؛ فرمان نهایی user.js create username است.

## آزمون و ساخت

```sh
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm audit
npm --prefix server audit
```

آزمون مرورگر از خروجی dist و دیتابیس موقت استفاده می‌کند و داده‌ی واقعی را تغییر نمی‌دهد. پورت 5190 باید آزاد باشد. test-results و playwright-report گزارش و تصویر خطاها را نگه می‌دارند. CI مراحل بررسی کد، API، مرورگر و ساخت Docker را دارد.

npm start خروجی ساخته‌شده‌ی dist و API را با هم ارائه می‌کند. فایل‌های آپلود از مسیر عمومی /uploads سرو نمی‌شوند و فقط از /api/files/:id با نشست معتبر قابل دریافت‌اند.
